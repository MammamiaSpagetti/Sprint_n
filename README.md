# Sprint_n — Яндекс.Маршруты

UI-тесты учебного сервиса [Яндекс.Маршруты](https://qa-routes.education-services.ru/): Python, Selenium, pytest, Page Object Model и Allure.

## Требования и установка

Python 3.12+, Chrome, Java 11+ и Allure Commandline 2.

Создание виртуального окружения и установка зависимостей. Команды PowerShell выполняются из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Selenium Manager подбирает ChromeDriver автоматически. Переменные `CHROMEDRIVER` и `CHROME_BINARY` позволяют указать пути к драйверу и браузеру.

## Запуск тестов

Запуск в headless-режиме:

```powershell
.\.venv\Scripts\python.exe -m pytest --clean-alluredir
```

Запуск с видимым окном Chrome:

```powershell
.\.venv\Scripts\python.exe -m pytest --headed --clean-alluredir
```

Адрес и пределы явных ожиданий настраиваются при запуске:

```powershell
.\.venv\Scripts\python.exe -m pytest --base-url https://qa-routes.education-services.ru/ --ui-timeout 20 --search-timeout 90
```

Также поддерживается переменная окружения `BASE_URL`. Каждый тест получает отдельную браузерную сессию. Проверки завершённого заказа ожидают окончания таймера поиска машины, поэтому полный прогон занимает несколько минут.

## Покрытие

Всего 30 тестовых случаев с учётом параметризации.

Результаты прогона от 24 сентября 2026 года: **28 passed, 2 xfailed** в обычном режиме; **28 passed, 2 failed** с `--runxfail`. HTML-отчёт сформирован по прогону с `--runxfail`. Окружение и длительности приведены в [docs/TEST_RUN.md](docs/TEST_RUN.md).

| Модуль | Класс | Проверки |
| --- | --- | --- |
| `test/test_route_rendering.py` | `TestRouteRendering` | Две видимые точки, их адреса и различающиеся координаты, карта справа; оба направления |
| `test/test_route_selection.py` | `TestRouteSelection` | Блок под адресами; одинаковые адреса дают «Авто Бесплатно В пути 0 мин.» |
| `test/test_taxi_preparation.py` | `TestTaxiPreparation` | Переключение режимов туда и обратно, цена и время, все шесть типов передвижения, кнопки Такси и Драйв |
| `test/test_taxi_tariffs.py` | `TestTaxiTariffs` | Шесть тарифов, один активный, шесть подсказок, поля и кнопка заказа |
| `test/test_taxi_order_flow.py` | `TestTaxiOrderFlow` | Рабочий со столиком, поиск и обратный отсчёт, назначение машины, водитель, детали, цена, отмена, полный сценарий |

При переключении режимов проверяются изменение стоимости, положительная длительность и восстановление исходных данных при возврате к оптимальному маршруту. Длительность быстрого маршрута не должна превышать длительность оптимального.

Иконка `i` появляется у выбранного тарифа, поэтому перед наведением тест выбирает нужную карточку. Изображения проверяются на видимость и успешную загрузку; картинка назначенной машины сравнивается с картинкой выбранного тарифа. Стоимость берётся из формы до отправки заказа и сравнивается с деталями.

## Структура

```text
Sprint_n/
├── data.py                 # Адреса, тарифы, тексты и ожидаемые значения
├── conftest.py             # Предусловия, браузер и вложения Allure
├── locators/               # Все Selenium-локаторы
├── pages/                  # Объекты экрана маршрутов, формы и окна заказа
├── test/                   # Пять тематических модулей и классов
├── docs/BUGS.md            # Подтверждённые расхождения с ТЗ
├── docs/TESTING_NOTES.md    # setTimeout, hover, xfail
├── docs/TEST_RUN.md        # Окружение и результаты прогонов
├── allure-report/         # HTML-отчёт
├── pytest.ini
└── requirements.txt
```

В объектах страниц используются только именованные локаторы из `locators/`. Тесты обращаются к интерфейсу через методы Page Object. Ожидания выполнены через `WebDriverWait`; `sleep` и неявные ожидания не используются.

## Дефекты и Allure

Две проверки описаний помечены `@pytest.mark.xfail(strict=True, raises=AssertionError)`: у тарифов «Сонный» и «Разговорчивый» перепутаны тексты. Ожидания соответствуют ТЗ. Подробности — в [docs/BUGS.md](docs/BUGS.md).

В обычном режиме известные расхождения отмечаются как `XFAIL`. Параметр `strict=True` делает неожиданный успех ошибкой `XPASS(strict)`. Параметр `raises=AssertionError` ограничивает ожидаемое падение ошибками утверждений; исключения Selenium остаются обычными ошибками прогона.

Для отображения известных дефектов как падений в Allure используется `--runxfail`. Параметр отключает обработку маркеров для конкретного запуска:

```powershell
.\.venv\Scripts\python.exe -m pytest --runxfail --clean-alluredir
allure generate allure-results --clean -o allure-report
allure open allure-report
```

При существующих дефектах pytest возвращает код `1`; генерация отчёта выполняется отдельной командой после завершения тестов. В отчёт входят шаги действий, скриншоты, HTML при расхождении, параметры окружения и категория известного дефекта. Команда `allure open` запускает локальный HTTP-сервер для просмотра отчёта.

Результаты pytest сохраняются в `allure-results/`, сформированный HTML-отчёт — в `allure-report/`.
